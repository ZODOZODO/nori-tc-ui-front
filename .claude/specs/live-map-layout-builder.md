# SPEC: live-map-layout-builder

> live-map 페이지를 (1) 실제 라인 모델 기반으로 재편하고 (2) admin 이 2.5D 캔버스로
> 구조물·설비를 저작·영속화하는 기능. 거대 범위라 **2 Phase** 로 분할한다.
> req 3(우측 이동)·req 4(선택설비 슬라이드)는 본 SPEC 범위 밖에서 이미 구현 완료(아래 "선행 완료").

## Why

- live-map 의 라인/배치가 전부 mock·하드코딩이다. **실제 "라인" 개념이 DB 에 존재하지 않는다**:
  - `tc_eqp` 에 line 컬럼 없음 ([postgres_create_all_table.sql:326-355](../../../nori-tc-exec/docs/db_table/create_all_table/postgres_create_all_table.sql)), `tc_line` 테이블 없음.
  - 백엔드가 모든 설비를 `DEFAULT_LINE_VALUE="A_LINE"` 로 강제 ([LiveMapQueryService.java:30-31,77-78](../../../nori-tc-ui-backend/ui/tc-ui-core/src/main/java/com/nori/tc/ui/core/service/LiveMapQueryService.java)).
  - "cluster" 는 실제 그룹이 아니라 `PROCESS_TYPE` param 에서 클라이언트 계산.
  - 좌표(`LIVE_MAP_CLUSTER_ITEMS`)는 프론트 mock, 영속화 안 됨.
- 따라서 "라인별로 설비를 정확히 나눈다"는 요구는 **신규 `tc_line` 테이블 + `tc_eqp.line_key` NOT NULL FK 도입** 없이는 불가능하다(데이터에 라인이 없으므로).
- admin 이 물리 라인 맵(구조물 + 설비)을 2.5D 캔버스로 저작·DB 저장하고, 비-admin 은 위치 이동 불가(읽기 전용)로 동일 맵을 봐야 한다.
- 상단바에서 라인을 선택하면 해당 라인 스코프의 설비만 보는 운영 시나리오.

## 영향 레포 + tc_eqp 다운스트림 (워크스페이스 전체 검증 완료)

`tc_eqp` 는 nori-tc-common 의 **공유 DB 레이어**에 매핑되어 gateway/business/ui-backend 가 모두 사용한다.

| 레포 | tc_eqp 사용 | line_key 추가 영향 |
|---|---|---|
| **nori-tc-common** | `TcEqp` 도메인 record([TcEqp.java:40](../../../nori-tc-common/db/tc-db-domain/src/main/java/com/nori/tc/db/domain/eqp/TcEqp.java)) + **JPA**(`TcEqpEntity`/mapper) + **MyBatis**(`TcEqpMapper.xml`/store) 두 ORM. INSERT/UPDATE/컬럼 fragment `TcEqpColumns` 포함 | **핵심 변경 대상**. 두 ORM 모두 line_key 매핑 + INSERT 반영. record 생성자 변경 → publish 발행 |
| **nori-tc-ui-backend** | 공유 `TcEqpStore` 사용 + 자체 UiEqp 매핑 | eqp 생성/수정에 line_key 필수. live-map 라인 조인 |
| **nori-tc-gateway** | `TcEqp`+`TcEqpStore` **READ-ONLY**, 로딩·라우팅 `route_partition IN(...) AND enabled` 기준([GatewayEquipmentService.java:113,205](../../../nori-tc-gateway/gateway/adapter/tc-gateway-db-adapter/src/main/java/com/nori/tc/gateway/adapters/db/GatewayEquipmentService.java)). INSERT 0건 | **런타임 쿼리에 line 조건 불필요**(라우팅=partition). 공유 record 변경 시 재컴파일 + 위치기반 `new TcEqp(...)` 테스트 수정만 |
| **nori-tc-business** | `route_partition` 메모리 스냅샷 READ-ONLY([BusinessEqpRoutePartitionDbAdapter.java](../../../nori-tc-business/business/adapter/tc-business-db-adapter/src/main/java/com/nori/tc/business/adapters/db/eqp/BusinessEqpRoutePartitionDbAdapter.java)). INSERT 0건 | gateway 와 동일 — 런타임 무관, 재컴파일/테스트만 |
| **nori-tc-exec** | 벤더별 DDL/패치 SQL | tc_line + tc_eqp.line_key 4 벤더 패치 |

**Kafka 메모리 갱신 경로**: ui-backend → gateway 설비 변경은 DB 재조회가 아니라 **Kafka 계약 `GatewayEquipmentProfileSnapshot`(nori-tc-common messaging)** 으로 전달되어 gateway 인메모리 `EquipmentContextRegistry` 를 재구성([GatewayUiRuntimeControlService.java:114-167](../../../nori-tc-gateway/gateway/adapter/tc-gateway-kafka-adapter/src/main/java/com/nori/tc/gateway/adapters/kafka/ui/GatewayUiRuntimeControlService.java)). 스냅샷은 명시 DTO 이므로 **line 을 계약에 추가하지 않으면 메모리 갱신 경로 영향 0**. gateway 는 line 불요 → **의도적으로 Kafka 계약에서 line 제외**(Constraints).

### tc_line 스키마 (tc_user_group 컨벤션 답습 — 사용자 확정)

`tc_user_group`([postgres_create_all_table.sql:918-933](../../../nori-tc-exec/docs/db_table/create_all_table/postgres_create_all_table.sql)) 의 code+name 마스터 컨벤션을 그대로 따른다. 감사컬럼은 created_at/updated_at 만, 정렬은 line_code 기준(sort_order 컬럼 없음 — 스키마 전체 선례 없음).

```sql
CREATE TABLE public.tc_line (
    line_key    BIGINT GENERATED BY DEFAULT AS IDENTITY,
    line_code   VARCHAR(50)  NOT NULL,
    line_name   VARCHAR(100) NOT NULL,
    description VARCHAR(1000) NULL,
    is_active   BOOLEAN NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT pk_tc_line PRIMARY KEY (line_key),
    CONSTRAINT uk_tc_line_line_code UNIQUE (line_code),
    CONSTRAINT ck_tc_line_is_active CHECK (is_active IN (TRUE, FALSE))
);
CREATE INDEX ix_tc_line_is_active ON public.tc_line (is_active);
```
`tc_eqp` 에는 `line_key BIGINT NOT NULL` 추가(위치: `eqp_id` 와 `comm_interface` 사이) + `CONSTRAINT fk_tc_eqp_line_key__tc_line FOREIGN KEY (line_key) REFERENCES public.tc_line(line_key)` + `CREATE INDEX ix_tc_eqp_line_key`. (벤더별 IDENTITY/BOOLEAN 표기는 각 벤더 create_all_table 관례 답습)

## Phase 2 — 2.5D 캔버스 빌더 + 레이아웃 영속화 (admin 전용)

> Phase 1 의 라인 스코프 위에서, 선택 라인의 캔버스를 admin 이 2.5D 로 저작·DB 저장.
> cluster 개념 폐기, 자유 도형 + eqpId 바인딩 설비 노드로 재설계. 비-admin 읽기 전용.

### 렌더링 기술 (확정)

- **확정: `react-konva`(Konva 2D 캔버스) + 2.5D 아이소메트릭.** (사용자 확정)
- 근거: 빌더(드래그/`Transformer`/레이어/히트테스트) 네이티브 지원, canvas 렌더라 다수 노드+실시간 갱신 성능 우위, React 19/Vite 정합(신규 의존성 1개), 진짜 3D 카메라 불요. 추후 3D 필요 시 `@react-three/fiber` 마이그레이션.

### 핵심 모델 — 합성(composite) 객체 + JSONB 자유 기하

객체는 **선·도형 여러 primitive 가 합쳐진 1개의 객체**다(예: 설비 1대를 사각형 + 선 + 텍스트 조합으로). 이 합성 객체를 DB 에 저장해두고 캔버스에서 우클릭 복사 / 우클릭 신규(팔레트)로 재사용·복제한다.

**스키마 원칙 — 식별/관계만 컬럼, 가변 기하·스타일은 JSONB.** 선/폴리곤/path 는 점 개수가 가변이고 2.5D 속성(깊이/skew/font/이미지src/path …)은 도형마다 다르다. 고정 컬럼으로 두면 새 도형·속성마다 DB 마이그레이션이 필요하다(이 스키마는 Flyway 없는 수동 4벤더라 변경 비용이 큼). react-konva 는 노드 트리를 `toJSON()`/`Node.create(json)` 로 직렬화하므로, 자유 기하·스타일은 **JSONB 1개**에 담아 **새 도형/속성 추가 시 DB 변경 0** 으로 만든다. JSONB 는 이 스키마의 기존 컨벤션이다(tc_deploy_* 의 `delta_json`/`snapshot_data_json`).

### 레이아웃/객체 스키마 (컨벤션 검증 완료)

마스터 명명 tc_user_group 답습, 부모-자식 `fk_<child>_<col>__<parent>` + `ON DELETE CASCADE`(tc_eqp_port_status 패턴), 가변 기하 JSONB. eqp 바인딩만 실데이터 참조라 FK 무결성 유지.

```sql
-- (1) 재사용 합성 객체: 선/도형 여러 개가 합쳐진 1개 객체. 기하 전부 JSONB.
CREATE TABLE public.tc_live_map_object (
    object_key   BIGINT GENERATED BY DEFAULT AS IDENTITY,
    object_name  VARCHAR(100) NOT NULL,
    object_kind  VARCHAR(20)  NOT NULL,          -- STRUCTURE / EQUIPMENT
    shape_json   JSONB NOT NULL,                  -- konva 직렬화: primitive 트리 + 좌표 + 스타일 전부
    is_active    BOOLEAN NOT NULL DEFAULT TRUE,
    created_at   TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at   TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT pk_tc_live_map_object PRIMARY KEY (object_key),
    CONSTRAINT uk_tc_live_map_object_object_name UNIQUE (object_name),
    CONSTRAINT ck_tc_live_map_object_object_kind CHECK (object_kind IN ('STRUCTURE','EQUIPMENT')),
    CONSTRAINT ck_tc_live_map_object_is_active CHECK (is_active IN (TRUE, FALSE))
);
CREATE INDEX ix_tc_live_map_object_is_active ON public.tc_live_map_object (is_active);

-- (2) 라인당 1 캔버스
CREATE TABLE public.tc_live_map_layout (
    layout_key   BIGINT GENERATED BY DEFAULT AS IDENTITY,
    line_key     BIGINT NOT NULL,
    canvas_json  JSONB NULL,                      -- 크기/배경/그리드 메타(가변)
    created_at   TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at   TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT pk_tc_live_map_layout PRIMARY KEY (layout_key),
    CONSTRAINT uk_tc_live_map_layout_line_key UNIQUE (line_key),       -- 라인당 1
    CONSTRAINT fk_tc_live_map_layout_line_key__tc_line
        FOREIGN KEY (line_key) REFERENCES public.tc_line(line_key) ON DELETE CASCADE
);
CREATE INDEX ix_tc_live_map_layout_line_key ON public.tc_live_map_layout (line_key);

-- (3) 라인 캔버스에 놓인 객체 인스턴스 (우클릭 복사/신규 = 새 행)
CREATE TABLE public.tc_live_map_placement (
    placement_key  BIGINT GENERATED BY DEFAULT AS IDENTITY,
    layout_key     BIGINT NOT NULL,
    object_key     BIGINT NOT NULL,
    eqp_key        BIGINT NULL,                   -- EQUIPMENT 객체면 실설비 바인딩(FK 무결성)
    transform_json JSONB NOT NULL,                -- x/y/rotation/scale/z 등 배치 변환(가변)
    created_at     TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at     TIMESTAMPTZ(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT pk_tc_live_map_placement PRIMARY KEY (placement_key),
    CONSTRAINT fk_tc_live_map_placement_layout_key__tc_live_map_layout
        FOREIGN KEY (layout_key) REFERENCES public.tc_live_map_layout(layout_key) ON DELETE CASCADE,
    CONSTRAINT fk_tc_live_map_placement_object_key__tc_live_map_object
        FOREIGN KEY (object_key) REFERENCES public.tc_live_map_object(object_key) ON DELETE CASCADE,
    CONSTRAINT fk_tc_live_map_placement_eqp_key__tc_eqp
        FOREIGN KEY (eqp_key) REFERENCES public.tc_eqp(eqp_key) ON DELETE CASCADE
);
CREATE INDEX ix_tc_live_map_placement_layout_key ON public.tc_live_map_placement (layout_key);
CREATE INDEX ix_tc_live_map_placement_object_key ON public.tc_live_map_placement (object_key);
CREATE INDEX ix_tc_live_map_placement_eqp_key   ON public.tc_live_map_placement (eqp_key);
```
> `object_kind='EQUIPMENT'` 배치는 `eqp_key` 필수, `'STRUCTURE'` 배치는 `eqp_key` NULL — 상호 배타는 서버 검증으로 강제. `shape_json`/`transform_json`/`canvas_json` 키 스키마(konva 직렬화 형식)는 아래 **「JSONB 키 스키마 동결」에서 확정(2026-06-02)**. **새 도형 타입·2.5D 속성 추가는 JSONB 라 DB 변경 없이 프론트만 확장**.

### JSONB 키 스키마 동결 (Phase 2 Specify — 2026-06-02 확정)

> 3 JSONB 컬럼의 키 계약만 동결한다. **DDL/FK/CHECK 는 이미 확정(위) — 불변**. 본 절은 컬럼 *내용*의 키 스키마를 정한다.
> 직렬화 원천은 **Konva `node.toObject()`** — `{attrs, className, children?}` 트리, 기본값 생략, 컨테이너 노드만 `children`, `Node.create(json)` 로 복원(검증: konva `src/Node.ts`). 3 컬럼 모두 최상위에 **스키마 버전 `v`(현재 `1`)** 를 둔다 — konva 메이저 버전업 시 직렬화 형식 변동을 식별하기 위함(JSONB 라 키 추가 비용 0, tc_deploy_* JSONB 선례 존재).

#### (a) `tc_live_map_object.shape_json` — 합성 객체 원형 (Konva `Group` 직렬화)

| 키 | 타입 | Null | 의미 |
|---|---|---|---|
| `v` | number | NOT NULL | 스키마 버전(현재 `1`) |
| `root` | object | NOT NULL | Konva `Group` 의 `toObject()` 결과(합성 객체 = primitive 트리) |
| `root.className` | string | NOT NULL | 루트는 `"Group"` 고정 |
| `root.attrs` | object | NOT NULL | Group attrs(기본값 제외). 좌표는 **객체 로컬 원점(0,0) 기준** |
| `root.children[]` | array | NOT NULL | primitive 노드 배열. 각 원소 `{attrs, className, children?}` |

primitive `className` 화이트리스트(1차): `Rect` / `Line` / `Text` / `Image`. (추후 `RegularPolygon`/`Path`/`Circle` 등은 **JSONB 라 DB 변경 없이 프론트만 추가**.) 노드별 대표 attrs(전부 Konva 네이티브, 기본값 생략):

- `Rect`: `x,y,width,height,fill,stroke,strokeWidth,cornerRadius,opacity`
- `Line`: `points([x1,y1,x2,y2,…]),stroke,strokeWidth,closed,dash`
- `Text`: `x,y,text,fontSize,fontFamily,fontStyle,fill,align`
- `Image`: `x,y,width,height,src` — **`src`(URL 문자열) custom attr**. Konva `image`(HTMLImageElement)는 직렬화 불가(`toObject` 가 non-plain object skip)라 저장 금지. `Node.create` 후 `src` 로 이미지를 로드해 주입(Out of Scope: 바이너리 업로드 아닌 URL 참조만).

```json
{ "v": 1,
  "root": { "className": "Group", "attrs": { "name": "pump-01" },
    "children": [
      { "className": "Rect", "attrs": { "x":0,"y":0,"width":80,"height":40,"fill":"#888" } },
      { "className": "Line", "attrs": { "points":[0,40,80,40],"stroke":"#444","strokeWidth":2 } },
      { "className": "Text", "attrs": { "x":4,"y":4,"text":"P-01","fontSize":12 } } ] } }
```

#### (b) `tc_live_map_placement.transform_json` — 배치 변환 (skew 기반 의사 2.5D)

객체 원형을 라인 캔버스에 놓을 때의 변환. 화면 좌표는 `x/y` 직접, 아이소메트릭 외관은 `skewX/skewY` 로 표현(논리 아이소 좌표 투영 레이어 없음).

| 키 | 타입 | Null | Konva | 의미 |
|---|---|---|---|---|
| `v` | number | NOT NULL | — | 스키마 버전(현재 `1`) |
| `x` / `y` | number | NOT NULL | 네이티브 | 캔버스 절대 좌표(px) |
| `rotation` | number | NOT NULL | 네이티브 | 회전(deg) |
| `scaleX` / `scaleY` | number | NOT NULL | 네이티브 | 배율 |
| `skewX` / `skewY` | number | NOT NULL | 네이티브 | **2.5D 아이소메트릭 기울임** |
| `zIndex` | integer | NOT NULL | 네이티브 | 형제 간 draw order |
| `depth` | number | NOT NULL | custom | **2.5D painter 깊이 정렬 가중치**(겹침 정렬용, `zIndex` 와 별개) |

**2.5D 아이소메트릭 필드 동결 목록**: `skewX`, `skewY`(외관 기울임) + `depth`(겹침 정렬). 그 외 좌표/변환은 `x,y,rotation,scaleX,scaleY,zIndex`(전부 Konva 네이티브). 진짜 3D 깊이축(논리 elevation) 미도입 — Out of Scope.

```json
{ "v":1, "x":320,"y":180, "rotation":0, "scaleX":1,"scaleY":1, "skewX":0,"skewY":0, "zIndex":5, "depth":12 }
```

#### (c) `tc_live_map_layout.canvas_json` — 캔버스 메타 (크기/배경/그리드)

DDL 상 NULL 허용(신규 layout 은 비어 생성 가능). 비면 프론트 기본값 적용.

| 키 | 타입 | Null | 의미 |
|---|---|---|---|
| `v` | number | NOT NULL | 스키마 버전(현재 `1`) |
| `width` / `height` | number | NOT NULL | Stage 크기(px) |
| `background` | string | NOT NULL | 배경색(hex/rgba) |
| `grid` | object | NOT NULL | `{ visible: boolean, size: number(px), color: string }` |

```json
{ "v":1, "width":1920,"height":1080, "background":"#0b0f1a", "grid":{ "visible":true,"size":32,"color":"#1e2638" } }
```

#### (d) EQUIPMENT / STRUCTURE ↔ `eqp_key` 서버 검증 규칙 (명문화)

`placement` 는 `object_key` 로 객체를 참조한다. 서버는 PUT 수신 시 해당 object 의 `object_kind` 를 조회해 다음을 **강제**(DB CHECK 불가 — `object_kind` 가 타 테이블이므로 **서버 검증으로만**):

- `object_kind = 'EQUIPMENT'` → `eqp_key` **NOT NULL 필수**. NULL 이면 거부(400).
- `object_kind = 'STRUCTURE'` → `eqp_key` **NULL 강제**. 값이 있으면 거부(400).
- `eqp_key` 가 주어지면 `tc_eqp` 존재 + 해당 layout 의 `line_key` 와 동일 라인 소속(Phase 1 스코프) 검증. 위반 시 FK 500 이 아닌 **명시 400**.

- 레이아웃 스키마: **식별/관계/eqp 바인딩만 컬럼, 가변 기하·스타일은 JSONB**(tc_live_map_object.shape_json / tc_live_map_placement.transform_json / tc_live_map_layout.canvas_json). 새 도형·2.5D 속성 추가 시 DB 마이그레이션 0. DB 변경 비용(수동 4벤더, Flyway 없음)이 커서 채택. (사용자 확정)

- **D3 편차 명시(권한)**: SPEC Phase 2 본문은 `LIVE_MAP_LAYOUT_WRITE` enforce 만 명시했으나, GET layout 을 비-admin 에 열려면 **신규 `LIVE_MAP_LAYOUT_READ`(PREFIX `/api/live-map/layout`, `http_method='GET'` 한정, ADMIN/DEVELOPER/OPERATOR)** 가 추가됐다. closed-by-default + ANY-of 매칭에서 READ 를 GET 한정해야 PUT/POST/DELETE 가 WRITE 권한에만 매칭 → 비-admin write 403(이중 차단 백엔드 절반).
